## Установленная техническая причина

После получения результата локально перерендерен candidate 0 серии 74:

```text
images shape: (51, 2, 32, 48, 3)
unique RGB frames: 1
changed RGB values between adjacent frames: 0
maximum feature standard deviation: 8,88e-16
command standard deviations: 22,33–28,45°
```

Команды всех шести суставов существенно менялись, но RGB-кадры оставались абсолютно одинаковыми.

Причина находится в сочетании геометрии и renderer:

1. серия 74 задала все подвижные сегменты лап MuJoCo-геометрией `capsule` через `fromto`;
2. используемый упрощённый software renderer из серии 38 аппроксимирует каждую геометрию как эллипсоид и делит координаты на все три компонента `model.geom_size`;
3. у capsule две компоненты размера равны нулю;
4. возникают divide-by-zero/invalid warnings, пересечение не формируется, подвижные лапы не попадают в изображение;
5. камера видит только неизменные тело и голову;
6. ridge получает постоянные признаки и сводится к одной средней команде.

Это не отрицательный результат о возможности распознавать grooming. Это **невалидный научный прогон из-за дефекта визуального стимула**. Восемь часов обучения не могли исправить отсутствие движения во входных данных.

## Аудит похожести

Аудит охватил 128/80 794 training motions и не был полным. В выбранной выборке среди 490 holdout-кадров:

- ближе 0,001°: 0;
- ближе 1°: 0;
- ближе 5°: 93.

Этот аудит сравнивает команды. Он не обнаруживает главный дефект, потому что RGB всех движений одинаков. Для следующего запуска обязателен отдельный preflight-инвариант: несколько различных команд должны давать разные RGB SHA и ненулевую дисперсию признаков.

## Решение для следующей серии

Серию 74 нельзя продолжать или переоценивать как grooming-эксперимент. Нужна новая серия с новым номером и frozen протоколом:

- заменить capsule на совместимые с renderer эллипсоидные сегменты с ненулевыми тремя размерами или расширить renderer корректной обработкой capsule;
- до длительного запуска проверять число уникальных RGB кадров;
- требовать ненулевую дисперсию visual features;
- выполнять sensitivity-тест каждого сустава: изменение только одного сустава должно менять RGB;
- только после этих guards разрешать восьмичасовой budget;
- сохранить строгий primary для каждого сустава.

## Ограничения проверки

Оригинальные локальные артефакты результата не проверены. Диагностика выполнена на закреплённом коде серии 74 и одном детерминированном candidate; этого достаточно для выявления постоянного RGB, но не для проверки пользовательской локальной файловой системы.
