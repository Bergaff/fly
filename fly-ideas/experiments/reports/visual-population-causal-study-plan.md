# Серия 71: причинная роль зрительных популяций в отложенном повторе

## Вопрос

Какие выходные популяции pretrained FlyVis и соответствующие после проверки клетки FlyWire v630 необходимы, чтобы после наблюдения и задержки сформировался автономный повтор движения второй цифровой мухи?

## Что уже реализовано

`71_visual_population_causal_study.py` фиксирует протокол до результатов, автоматически находит последний полный запуск серии 69, перерендеривает frozen holdout 51–55 в две камеры, преобразует RGB официальным BoxEye и записывает центральную активность всех выходных типов pretrained FlyVis. Затем он создаёт только кандидаты точных соответствий с таблицей нейронов и блокирует лезии до явной проверки mapping. Запуск без командной строки: `RUN-VISUAL-POPULATION-CAUSAL-STUDY.bat`; пункт 2 сам создаёт папку и открывает её после успеха. Для Windows пять FlyVis capture выполняются последовательно в отдельных процессах. Также используется локальный runtime-workaround дефекта datamate 1.0 `_write_h5`: существующий cache с dataset и ожидаемыми shape/dtype не переписывается; для нового или оборванного cache оригинальный writer на Windows вообще не вызывается, запись идёт в закрытый временный HDF5 с последующим `os.replace`. Это необходимо, потому что datamate 1.0 открывает новый файл в `w`, обращается к ещё не созданному dataset и в обработчике пытается удалить собственный открытый файл. Установленный FlyVis/datamate не модифицируется. Безопасный повтор продолжает ту же подготовленную папку и проверяет SHA готовых CSV.

Основной набор зафиксирован заранее: T4a–T4d и T5a–T5d. Условия: normal, восемь одиночных лезий, T4 вместе, T5 вместе, T4+T5, temporal shuffle, zero post-observation state и mapping permutation. Пять holdout 51–55, задержка 0,5 с, десять seeds.

## Критерий

Популяция называется необходимой только если её заранее заданная лезия ухудшает RMSE шести углов относительно парного normal в одном направлении минимум на четырёх из пяти holdout и эффект выдерживает mapping-permutation control. Главная величина: изменение RMSE в радианах; дополнительно сохраняются ошибка каждой оси, удержание состояния и активность заранее проверенных readout.

## Научные gate

1. Retinal movie должен быть настоящим входом для FlyVis, а не activity серии 69.
2. `mapping_candidates.csv` не является mapping. Совпадение названий лишь формирует список для проверки.
3. Для утверждения нужны FlyWire ID, источник evidence, знак и заранее заданное правило activity→Hz для всех восьми типов.
4. Только после `mapping_gate.json: passed=true` реализуется и запускается Shiu lesion runner.
5. FlyGym не участвует в основном критерии, пока отдельно не закреплён motor readout.

## Текущий статус

Код этапа A готов: preregistration, FlyVis capture, mapping candidates и строгий validator. Реальный причинный результат ещё отсутствует. Следующий инженерный шаг после получения retinal movie и утверждённого mapping: runner одинакового Shiu input stream для normal и всех preregistered lesions с транзакционным checkpoint.
