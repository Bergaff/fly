# Fly Ideas

Десктоп-программа (Windows 10+) для работы с идеями научных статей на модели мозга мухи:
просмотр, оценка по пяти шкалам, статусы от бэклога до публикации, сравнение на радаре,
перенос идей между проектами.

Стек: Vite + React 19 + Tailwind v4 + shadcn/ui (new-york) + чарты в духе [Bklit](https://bklit.com) на recharts + Electron.

## Запуск на Windows (без консоли)

Нужен только [Node.js](https://nodejs.org) 22+ (LTS). Дальше:

| Файл | Что делает |
| --- | --- |
| `START.bat` | Двойной клик: открывается окно программы. При первом запуске сам докачает зависимости. |
| `BUILD-EXE.bat` | Собирает портативный `release\Fly-Ideas-0.1.0-win64.exe`, можно носить на флешке без установки. |

## Вручную (если хочется)

```powershell
cd fly-ideas
npm install
npm run electron:dev   # окно программы + горячая перезагрузка
npm run dev            # только в браузере, http://localhost:5173
npm run dist           # собрать .exe в release/
```

## Оформление

Внешний вид намеренно сдержанный: наборная вёрстка вместо витрины.

- палитра приглушённая: серо-коричневый, сталь, олива, охра, кирпич; отдельно тёмная и светлая темы, без чистого белого фона и фиолетового с чёрным;
- квадратные углы, волосяные линии, отсутствие теней, градиентов, размытия и скользящего стекла;
- подписи и числа моноширинные, цифры табличные, шапки разделов капслоком;
- ни одной пиктограммы: действия подписаны словами, состояния показаны квадратами и штриховкой;
- без анимаций: наведение и выбор меняют цвет мгновенно;
- интерфейс без всплывающих подсказок-украшений, счётчиков аналитики и заглушек-скелетонов.

## Данные: два коннектома, зачем оба

| Набор | Что это | Для чего в проекте |
| --- | --- | --- |
| **FlyWire v783** (самка, 139 тыс. нейронов) | женский мозг, аннотации типов клеток и предсказания нейромедиаторов 2024 года | основной для адаптаций и бенчмарков; авторский ноутбук Shiu использует v630, эквивалентность наборов необходимо проверять |
| **MaleCNS v1.0** (самец, 165 тыс. нейронов, около 12 тыс. типов клеток) | полная ЦНС самца: мозг, оптические доли и брюшная нервная цепочка с сохранённым шейным коннектором, релиз 2026 года, CC-BY 4.0 | для второго шага: пол и ухаживание, моторный выход вместо декодированного readout, сравнение полов |

MaleCNS скачивается во вкладке «Мозг» → «Данные и окружение»: аннотации (13 МБ) и предсказания нейромедиаторов (42 МБ). Крупные таблицы связности лежат в открытом бакете Google и берутся через neuPrint или инструменты Janelia: ссылки в разделе «внешние источники».

Готовой LIF-модели и бенчмарков на MaleCNS пока нет: перенос загрузчика fly-brain на мужские таблицы это отдельная методическая работа (идея «Память отвергнутого самца»).

## Ключи API

- **DeepSeek** (код): ключ с platform.deepseek.com, вставляется в панели помощника справа.
- **Perplexity** (поиск литературы): ключ с perplexity.ai/settings/api, там же.

Оба ключа лежат в файле `secrets.json` в папке данных приложения и передаются только в main-процесс: со стороны окна они недоступны. Запросы уходят на api.deepseek.com и api.perplexity.ai напрямую, без посредников.

### Подключение скачанных файлов

Во вкладке «Мозг» → «Данные и окружение» выберите вручную скачанные таблицы: связи, классификацию, типы клеток и нейромедиаторы. Файлы CSV, TSV, CSV.GZ, TSV.GZ и Parquet остаются на своих местах; приложение запоминает пути для всех идей. При каждом запуске пути передаются в `FLY_CONNECTOME`, `FLY_ANNOTATIONS`, `FLY_CELL_TYPES` и `FLY_NEUROTRANSMITTERS` соответственно (пустая строка означает, что файл не выбран). Чтобы проверить заголовок и до 20 первых строк таблиц, в любой идее откройте `21_check_linked_data.py` и запустите его. Итог будет в `summary.json`. Это не проверка версии, целой таблицы или соответствия ID между файлами.

Подключение не преобразует и не добавляет данные в старые скрипты автоматически: они должны явно читать эти переменные и поддерживать формат. В частности, существующие готовые анализы 10..19 используют свои исходные файлы в `FLY_DATA`, а не выбор выше; их результаты не следует приписывать выбранному файлу. Новому коду помощника сообщаются эти переменные, но проверяйте код перед запуском. Таблицы Codex Princeton и оригинальные исходные данные модели Shiu не следует считать эквивалентными без проверки источника и подготовки.

### Создание и изменение кода помощником

1. Во вкладке «Мозг» выберите идею и справа откройте «Помощник API», DeepSeek. Выберите формат «Только код» или «Код и пояснения». Для непонятного запроса модель может задать уточняющий вопрос.
2. Для нового `.py` включите «создание» и «автосохранение». Готовый блок с первой строкой `# file: имя.py` сохраняется в папку кода выбранной идеи, путь указан в панели. Модель сама файлы не записывает; запись выполняет приложение.
3. Для изменения существующего `.py` откройте его в дереве идеи, сохраните свои правки и включите «Передавать в DeepSeek открытый файл» и «изменение». Текст файла уходит в API вместе с запросом и расходует токены. Отправляйте только содержимое, которым готовы поделиться с провайдером.
4. Приложение записывает файл только в папку кода идеи, если права включены, исходник не изменился после запроса и ответ модели не оборван. Перед автоматической заменой создаётся резервная копия рядом с файлом с расширением `.bak-...`. Если файл изменился или в редакторе есть несохранённые правки, ответ не перезапишет его. Состояние сохранения показано под ответом.
5. Автосохранение не запускает код. Проверяйте скрипты и научные выводы до запуска; код, сгенерированный моделью, может содержать ошибки. Ручное сохранение блока из ответа запрашивает подтверждение при замене файла.

Для выбора другой папки используйте «папки и права» над рабочим местом. За пределами выбранной папки помощник автоматически файлы не меняет. Передача открытого файла выключена по умолчанию при открытии чата. Автосохранение распознаёт завершённые блоки Python с корректным именем, а не произвольный текст ответа.

Если помощник выдал код без ограждённого блока, приложение не угадывает его границы и не сохраняет его автоматически. В ответе выделите весь код от строки `# file: имя.py` до конца файла, без текста после него, и нажмите «сохранить выделенный код». Проверьте выделение и подтвердите сохранение. Для него должно быть включено право «создание»; создаётся только новый файл в выбранной идее, существующий файл не заменяется. Полнота и работоспособность кода автоматически не проверяются.


## Правовое

В меню приложения два документа: «Условия использования» и «Политика конфиденциальности». Коротко: программа работает локально, телеметрию не собирает, ключ DeepSeek лежит в файле `secrets.json` папки данных приложения, в сеть уходят запросы к DeepSeek или Perplexity при использовании помощника и загрузка открытых файлов данных. При выбранной синхронизации Google Диск передаёт снимки через Google Drive for desktop. История запросов API хранится локально в `api-calls.json` в папке данных приложения и входит в снимок синхронизации.

## Что внутри

- **Проект** — открывается выбором проекта в верхней строке. Название и описание правятся прямо здесь, цвет переключается пятью образцами. Сверху строка состояния: сколько идей, сколько этапов пройдено, прогонов, источников, что доведено до подачи, ближайший срок. Дальше три вещи: описание проекта, пути рабочего места (папка кода и папка прогонов, кнопки «Показать прогоны» и «Сменить папки», где каждая из двух папок переназначается или возвращается к значению по умолчанию) и таблица идей по приоритету. Ниже состояние по статусам, последние записи журнала и источники проекта. Главная кнопка — **«Начать проект»** (если работа ещё не начиналась) или **«Продолжить проект»**: она открывает рабочее место этого проекта, при первом входе создаются папки и копируются шаблоны.
- **Идеи** — плотная таблица: одна строка на идею (статус, оценки с сводным приоритетом, прогресс чеклиста, дедлайн, метки, счётчики источников и записей). Поиск, фильтр по статусу, сортировка по приоритету, влиянию, лёгкости, скорости или дате. Проект идеи можно изменить в её карточке. Клик открывает диалог с пятью вкладками:
  - **Разбор** — вопрос, метод, валидация, журналы, ссылки, заметки, оценки;
  - **Чеклист** — этапы «от идеи до статьи» (стандартный конвейер из 9 шагов, можно править, добавлять, перетаскивать; галочки хранят дату);
  - **Журнал** — лабораторный дневник: дата / что запускал / параметры (сид, бэкенд, коммит) / результат / вывод, исход «получилось / частично / нет / неясно», кнопка «повторить с теми же параметрами»;
  - **Источники** — статьи, привязанные к идее, с полем «зачем нужна здесь»; поиск по общей базе или создание нового источника на месте;
  - **внешний агент (MCP)**: мост к DeepSeek Harness, Claude Code или Codex. Агент видит идеи, журнал, литературу, данные и прогоны, запускает скрипты и пишет в журнал, а правки проходят через окно приложения с уведомлением. Включается в разделе «Данные и окружение».
  - кнопка **«Черновик статьи»** в шапке идеи собирает markdown: вопрос, метод, валидация, таблица прогонов из журнала, оценки, незакрытые этапы, литература со ссылками и DOI. Черновик можно скопировать или сохранить файлом `.md`;
  - **Связи** — «растёт из…» (какие идеи нужно сделать раньше) и обратные связи.
- **Библиотека** — общая база источников на все проекты: автор, год, название, журнал, DOI/URL, теги, конспект. Видно, в каких идеях источник используется и зачем. Фильтр по тегам, «только текущий проект», копирование списка литературы в буфер. Быстрый разбор строки с DOI/годом.
- **Дашборд** — карта «трудоёмкость × влияние» (размер точки — новизна), воронка статусов, дерево идей (граф зависимостей), список дедлайнов с подсветкой «скоро / просрочено», последние записи журнала, счётчики.
- **Сравнение** — радар до трёх идей и таблица по всем полям: оценки, этапы, сроки, источники, метки, выходы. Отметка для сравнения ставится галочкой в строке таблицы.
- **Проекты** — выбор в верхней строке, создание, переименование и удаление в меню рядом. Перенос идеи: меню «··· → Переместить в» или смена проекта в диалоге. Есть «Копировать в».
- **Мозг** (только в окне Electron): рабочее место проекта и отдельных идей. Переключатель «идея» создаёт отдельные папки кода и прогонов для каждой исследовательской идеи; проекты остаются верхним уровнем группировки. Папки проекта или идеи можно переназначить (например, на большой диск), выбор запоминается:
  - **слева дерево выбранной идеи**: исходное (вопрос, метод, проверка, ссылки), файлы расчёта и результаты с файлами каждого прогона. CSV и TSV доступны в виде таблиц, изображения показываются в результатах; крупные и двоичные файлы открываются из папки прогона;
  - **в центре код и результаты**: редактор, поле аргументов, запуск и остановка; внизу можно выбрать лог или файл результата и скопировать его содержимое. Кнопка «в журнал идеи» переносит прогон в лабораторный дневник;
  - **справа вкладка «По задачам (без API)»**: готовый проверенный код анализа под все 10 текущих исследовательских задач (`10..19` и общий модуль `flylib.py`), чтобы запускать расчёты локально на ПК без платной генерации с нуля через DeepSeek API. В каждой задаче три готовых режима одной кнопкой (`--synth` для мгновенной проверки, прогон на локальных данных `FLY_DATA` и расширенный протокол); файлы появляются в пространстве выбранной идеи;
  - **справа вкладка «Помощник API»**: DeepSeek для доработки кода и Perplexity для литературы. Ответ с блоком Python сохраняется в папку выбранной идеи, история чата разделена по идеям, строки с DOI из ответа Perplexity вносятся в библиотеку одной кнопкой. Под чатом находятся этапы выбранной идеи: они связаны с Дашбордом. По вашему сообщению о выполненной работе DeepSeek может отметить этап автоматически, результат следует проверить; статус можно изменить вручную;
  - **учёт API** в чате: каждый новый вопрос и ответ, в том числе поиск литературы из библиотеки, доступны в раскрываемой истории. Переключатель показывает текущую идею или все вызовы. Токены берутся из ответа провайдера; если он их не вернул, показано «н/д». Для приблизительной стоимости можно задать собственные тарифы за миллион входных и выходных токенов для каждой модели. Оценка не учитывает кэш и дополнительные сборы и не заменяет счёт провайдера. Данные сохраняются в открытом виде в `%APPDATA%\fly-ideas\api-calls.json`, отдельно от экспорта состояния; очистка чата журнал не удаляет. Вызовы до установки этой версии задним числом не восстанавливаются;
  - **права помощника**: создавать файлы, перезаписывать существующие, разрешать запуск скриптов. Права проверяются в main-процессе, а не в интерфейсе;
  - **раздел «Данные и окружение»**: скачивание коннектома FlyWire v783, аннотаций Schlegel et al. 2024 и таблиц MaleCNS, проверка Python и пакетов, подключение внешнего агента MCP.

- **Данные** — хранятся локально (localStorage окна Electron). ⚙ → выгрузка/загрузка JSON через системный диалог выбора файла, сброс к стартовому набору. Список литературы из Библиотеки — в буфер или в файл.

## Папка workspace/

Создаётся рядом с программой при первом запуске (в git не попадает):

```
workspace/
  data/      скачанные данные коннектома
  scripts/   python-скрипты (шаблоны копируются из experiments/templates)
  runs/      результаты прогонов, по папке на запуск
```

Скрипт при запуске получает переменные окружения `FLY_DATA`, `FLY_RUN_DIR`, `FLY_SCRIPTS`.

Шаблоны и готовый код анализа задач в `experiments/templates/` (автоматически раскладываются в папку кода проекта и обновляются кнопкой `шаблоны`):

| `18_courtship_song_ipi.py` | задача `i-song`: слуховой каскад JO->AMMC->WED->vPN1->pC1, настройка на IPI 35 мс и сравнение статичного LIF с STP и тормозной задержкой |

Любую из папок можно переназначить кнопкой «выбрать»: выбор запоминается в `config.json` в папке данных приложения (`%APPDATA%\fly-ideas`), кнопка «сбросить» возвращает умолчание.

## Синхронизация между компьютерами через Google Диск

На обоих компьютерах установите Google Drive for desktop, войдите в один аккаунт и запустите Fly Ideas обычным двойным щелчком по `.bat`. В меню программы выберите «Синхронизация через Google Диск» и укажите одну и ту же папку на Диске. Путь на компьютерах может отличаться. Программа не подключается к Google API: файлы переносит установленное приложение Google Диска.

1. На первом компьютере сохраните открытый код и дождитесь окончания расчётов, загрузок и ответов помощника. Нажмите «Отправить снимок».
2. Дождитесь окончания загрузки в самом приложении Google Диска. Сообщение Fly Ideas означает лишь, что снимок записан в локальную папку, но ещё не обязательно загружен в облако.
3. На втором компьютере дождитесь скачивания файлов Google Диском, откройте тот же раздел, обновите список, выберите снимок и нажмите «Загрузить выбранный снимок».

В снимок входят идеи, этапы, источники, журнал экспериментов, код и результаты каждого проекта и идеи, история чатов, тарифы и журнал API. Папку данных и вручную подключённые таблицы можно включить отдельно: это может занять много места, времени и трафика. На принимающем компьютере таблицы копируются в папку данных, а привязки обновляются. API-ключи, остальные настройки и Python-окружение не переносятся: настройте их на каждом компьютере. Если вы сами записали секреты в код, результаты или чат, они попадут в снимок. Снимки не имеют дополнительного сквозного шифрования.

Каждая отправка создаёт отдельный снимок. Автоматического объединения изменений нет: загрузка заменяет локальное состояние, чаты, журнал API и файлы с совпадающими именами; лишние локальные файлы не удаляются. Если работали на обоих компьютерах независимо, отправьте оба снимка, прежде чем загружать один из них. Перед каждой загрузкой создаётся локальная резервная копия; её можно выбрать в списке «Локальные резервные копии» того же диалога. Резервные копии находятся в `%APPDATA%\fly-ideas\sync-backups` и не заменяют отдельное внешнее резервирование.

Проверяются размеры и SHA-256 файлов. Неполный или повреждённый снимок не применяется. Если восстановление прервано после создания копии, часть файлов уже могла измениться: откройте указанную локальную резервную копию. Папка синхронизации не должна пересекаться с папками кода, результатов или данных. Символические ссылки внутри синхронизируемых папок не поддерживаются. Не изменяйте эти файлы другой программой во время копирования. Для данных и снимков нужно достаточно свободного места на обоих компьютерах и на Диске.

## Научный прогресс и предложения в чате

У каждой идеи есть отдельный научный прогресс: наблюдение, воспроизведение, интерпретация и верификация. Откройте карточку идеи из списка идей или кнопкой «карточка» в «Мозге», затем перейдите на вкладку «Прогресс». Здесь можно вручную отметить этап и записать основание, например путь к результату или описание контроля. Сохраните изменения кнопкой «Сохранить». Сводка видна на Дашборде. Процент показывает только число пользовательских отметок из четырёх, а не доказанность или качество исследования. Существующие этапы подготовки статьи сохранены отдельно и не превращаются автоматически в научные отметки.

В чате кнопка «Получить от DeepSeek» запрашивает предложения для выбранной идеи. Это отдельный API-запрос с расходом токенов; самостоятельно и при переключении идей он не запускается. Передаются название, вопрос, метод, проверка, отметки и основания научных этапов и две последние записи журнала. История чата и открытый файл в этом запросе не передаются. Нажатие на предложение только помещает текст в поле ввода. Предложения относятся к состоянию идеи на момент запроса, могут быть ошибочными и не запускают код. Кнопка «предложения: вкл/выкл» скрывает или включает раздел на этом компьютере; отключение не отменяет запрос, который уже отправлен. Учёт этих запросов сохраняется в общем журнале API.

## Тест Brian2 на подключённых таблицах

В рабочих пространствах идей доступен `small_sample_lif_fixed.py`. Это отдельный исправленный вариант скрипта `small_sample_lif.py`; существующий пользовательский файл не заменяется. Если файл `small_sample_lif_fixed.py` уже существует, программа его тоже не перезапишет.

В «Мозге» → «Данные и окружение» подключите таблицы связей и нейромедиаторов. Этот тест использует только `FLY_CONNECTOME` и `FLY_NEUROTRANSMITTERS`; аннотации и типы клеток ему не нужны. Для него поддерживаются CSV и CSV.GZ с колонками `pre_root_id`, `post_root_id`, `syn_count` в связях и `root_id`, `nt_type` в таблице медиаторов. Доступность и названия колонок ещё не подтверждают версию данных или совместимость с моделью Shiu.

Откройте файл в дереве идеи и нажмите «запустить». По умолчанию выбираются до 2000 нейронов; исходная таблица связей читается частями в два прохода, поэтому проверка большого файла может быть долгой. Итог записывается в `summary.json`, `sample_rates.csv` и `spikes.csv`; `sample_index` это индекс в подвыборке, а `source_root_id` это точный ID из исходной таблицы. Исходные данные не изменяются.

В варианте исправлены параметры Brian2, размерности и использование `dt`, а синаптический ток затухает с условной постоянной времени 5 мс. Для технического теста только ACh назначается положительный знак, а GABA отрицательный. Связи с другими и отсутствующими обозначениями медиатора исключаются и перечисляются в отчёте; это не утверждение об их реальном действии. Если подходящих связей нет, отчёт указывает, что смоделированы независимые нейроны. Отбор нейронов и модель отличаются от исходного пользовательского варианта, результаты напрямую не сопоставимы. Веса и параметры не калиброваны; скрипт не является воспроизведением Shiu и не доказывает биологическую интерпретацию.

### Копирование результатов

В «Мозге» выберите прогон и файл для просмотра на панели результатов или в дереве слева: например, `summary.json`, `sample_rates.csv` или `spikes.csv`. Выбор файла сам по себе не копирует его. Нажмите отдельную кнопку «копировать summary.json» над предпросмотром и дождитесь сообщения об успешном копировании. Для текстовых файлов приложение проверяет содержимое буфера; если подтвердить запись не удалось, появится ошибка. Переключатель «показать лог» возвращает копирование к логу выбранного прогона. Пока прогон выполняется и не выбран сохранённый прогон, копируется видимая часть текущего лога.

CSV и TSV копируются как исходный текст, а не видимая часть таблицы; PNG/JPEG как изображение, SVG как текст. Предпросмотр может быть ограничен, но текстовые файлы и изображения до 8 МиБ копируются целиком. Файлы большего размера и неподдерживаемых форматов, например Parquet, XLSX или GIF, откройте через кнопку «папка» и копируйте обычным способом. При ошибке приложение не подставляет лог вместо выбранного файла.

### Сверка ID для эксперимента Shiu

В пространстве каждой идеи доступен `22_shiu_reference_check.py`. Он читает подключённые в «Данные и окружение» таблицы целиком, частями, и подсчитывает в них совпадения с ID sugar GRN и MN9 из авторского `figures.ipynb` (точный коммит указан в отчёте). На больших таблицах проверка может занять время. Входные файлы не изменяются; итог находится в `summary.json` прогона. Статус `ok` означает только завершение чтения связей, а не подтверждение модели. Совпадение ID не устанавливает соответствия версий FlyWire, исходной связности или корректности модели. Для фактического расчёта нужен отдельно проверенный протокол и совместимые данные. Симуляция не запускается.

### Подготовка адаптированного расчёта sugar GRN → MN9

В каждой идее доступен `23_shiu_mn9_adapted.py`. Обычный запуск без аргументов целиком читает подключённые CSV/CSV.GZ связей и медиаторов, проверяет IDs из авторского ноутбука и три предложенных независимым проектом кандидата v783, подсчитывает строки по типу медиатора и записывает `summary.json`. Совпадение ID и наличие кандидатов не доказывает их идентичности; сравнение с авторскими таблицами связей скрипт не выполняет. Входы не изменяются, синтетическая сеть не создаётся. При отсутствии необходимых ID или ошибках расчёт блокируется.

Отдельный экспериментальный режим включается только явными аргументами `--simulate --accept-candidate-map --accept-exclusions`. Использовать его следует только после просмотра отчёта и понимания допущений. Требуются pandas, numpy и Brian2; по умолчанию он проводит один односекундный повтор при 100 Гц. Полный граф может потребовать нескольких гигабайтов RAM и длительного расчёта. В нём используются параметры LIF из авторского кода, но связность берётся из Princeton, а типы кроме ACh, GABA и glutamate исключаются. Таблица медиаторов используется по пресинаптическим ID; строки разных neuropil сохраняются отдельными связями. Кандидаты сопоставления не доказаны. Это не авторская подготовка коннектома и не точное воспроизведение Figure 1c. Частоту, сторону и число повторов (`--frequency-hz`, `--side`, `--n-trials`) и сделанные допущения скрипт записывает в отчёт.

### Сравнение пользовательской связности с Shiu v630

1. Откройте «Мозг» → «Данные и окружение». В поле «Таблица связей» оставьте свой файл `connections_princeton.csv` (или `.csv.gz`). В поле «Нейромедиаторы» можно оставить `neurons.csv`: он нужен для дополнительного сравнения знаков, но не для сравнения числа связей.
2. Там же по двум ссылкам GitHub скачайте авторские `2023_03_23_connectivity_630_final.parquet` и `2023_03_23_completeness_630_final.csv`. На каждой странице нажмите Download raw file. Выберите их отдельно в полях «Авторские связи Shiu v630» и «Авторский список нейронов Shiu v630». Они не заменяют ваши ранее выбранные файлы. Приложение сохраняет пути; сами файлы остаются на своих местах.
3. Вернитесь к коду выбранной идеи и в меню «проверки Shiu» выберите «сравнить связность». Используется `24_compare_shiu_connectivity.py`, который добавляется в существующие пространства без перезаписи файлов. Расчёт локальный и не использует API. Если не установлен `duckdb`, перейдите в «Данные и окружение», установите пакеты и повторите запуск вручную. Нужны также `pandas` и `matplotlib`.
4. После окончания выберите прогон в дереве результатов. Откройте `report.txt` для краткого объяснения, `comparison.csv` для показателей, `summary.json` для полного отчёта и контрольных сумм, `pairs.png` и `weights.png` для графиков. Выберите нужный файл и нажмите кнопку его копирования.

Скрипт проверяет соответствие авторских индексов ID из списка, суммирует строки выбранной таблицы по направленным парам и считает совпадения на точном пересечении ID. Версия авторских файлов проверяется по Git blob SHA-1 закреплённого коммита; при несовпадении происхождение не подтверждено. Происхождение пользовательской таблицы не проверяется. Нейроны с изменившимися ID не сопоставляются автоматически. Количество синапсов и знаки сравниваются отдельно; ACh считается возбуждающим, GABA и GLUT тормозящими, остальные медиаторы исключаются из сравнения знаков. Эти допущения могут отличаться от авторской подготовки. Индекс Жаккара и сравнение весов ограничены общими ID; веса и корреляция считаются по общим парам. Это не симуляция и не подтверждение воспроизведения Figure 1.

Большой расчёт может занять продолжительное время. DuckDB ограничивает собственную память 1 ГБ, но общий расход Python выше; может потребоваться несколько гигабайтов свободного места на диске **папки результатов идеи** для временных файлов. Входы только читаются. При нормальном завершении или ошибке временные файлы удаляются; при принудительной остановке может остаться папка `.compare_tmp-...` в папке прогона. Её можно удалить после остановки процесса. Эти папки не включаются в снимки синхронизации. После остановки или ошибки продолжение требует выбора папки прерванного прогона; исходные файлы прежнего прогона не меняются. Не выключайте компьютер во время записи; при прерывании храните всю папку прогона с контрольной точкой. Готового проверенного расчёта лезий пока нет.

### Исходящие лезии v630

В выбранной идее откройте **«лезии v630» → «пилот: контроль и одна лезия»**. Выберите папку завершённого полного отбора топ-200, где лежат `summary.json`, `top200.csv`, `checkpoint.json` и все 30 файлов `counts_seed_*.npy`. Система проверит авторские файлы, контрольные суммы всех повторов и пересчитает рейтинг перед использованием. Нужны те же версии Python, NumPy и Brian2, с которыми выполнен отбор. Проверенные копии кода лежат в `.shiu-lesions-v630` в папке кода этой идеи, существующие пользовательские файлы не заменяются.

Пилот считает контроль и лезию одного первого в списке нейрона, который не относится к стимулируемым GRN или MN9, при 100 Гц и seed 0. Это проверка исполнения, а не статистический вывод. После неё **«продолжить из папки лезий»** попросит сначала исходную папку топ-200, затем папку пилота с `lesions.sqlite3`, и рассчитает оставшийся полный план в новой папке. Оба сохранённых повтора пилота будут использованы. Папки прежних прогонов не изменяются. Кнопка **«начать полный расчёт»** начинает план с нуля.

Полный план содержит 8 частот 50–120 Гц, 30 seed, 200 лезий и отдельные контроли, всего 48 240 односекундных симуляций. Обычное продолжение работает в одном процессе; оно может занять недели и потребовать нескольких гигабайтов памяти. После каждого повтора данные фиксируются транзакцией в `lesions.sqlite3`, счётчик записывается в `progress.json`. При остановке выбирайте для продолжения именно папку наиболее полного прогона лезий, и сохраняйте также исходную папку топ-200. Протокол, хеши кода, исходных данных и файлов отбора, версия Python и библиотек должны совпадать. В случае ошибки или отсутствующего файла продолжение останавливается; данные не заменяются.

Для осторожного ускорения есть **«лезии v630» → «продолжить: 2 процесса»**. Перед обновлением и продолжением остановите идущий расчёт, дождитесь выхода процесса и сохраните папку его последнего прогона. После запуска приложения выберите сначала прежнюю папку полного топ-200, затем папку последнего прерванного прогона лезий с `lesions.sqlite3`, а не обязательно папку пилота. Приложение создаёт новую папку, копирует и проверяет базу, продолжает только недостающие повторы; исходная база не перезаписывается. Не запускайте старый и новый расчёты одновременно: повторы, записанные в старую базу после копирования, не попадут в новую. Старый скрипт `28_shiu_lesions_v630.py` не изменён. После остановки можно снова продолжить в одном процессе или в двух из папки последнего прогона.

Два процесса создают две большие сети, поэтому расход RAM заметно возрастёт; 16 ГБ общей памяти не гарантируют, что её хватит или что Word будет отзывчивым. Сохраните работу в Word перед началом и наблюдайте за памятью через диспетчер задач. В Windows режим не стартует при менее 8 ГиБ свободной физической памяти после загрузки входов. Если при выполнении остаётся менее 2 ГиБ, новые повторы прекращаются. Эти пороги не могут предотвратить внезапный рост потребления или гарантировать отсутствие подкачки. При нехватке памяти используйте последовательный режим. Рабочим процессам задан приоритет ниже обычного, а численным библиотекам по одному потоку; реальное ускорение зависит от памяти и компьютера, оно не измерено для полного графа.

Кнопка остановки параллельного режима запрашивает корректное завершение: дождитесь сообщения о выходе процесса. Один из выполнявшихся повторов или оба могут потребовать пересчёта, уже записанные транзакции сохраняются. Резкое выключение компьютера или принудительное завершение может прервать запись. При закрытии приложения предусмотрена попытка остановки расчёта на Windows, но безопаснее сначала нажать кнопку остановки и дождаться выхода процесса; не выключайте компьютер, пока процессы не завершились. `parallel_execution.json` и `summary.json` записывают режим, число процессов, ограничения потоков и хеш оболочки; для остановленного прогона `summary.json` содержит `status: stopped`. На синтетической сети проверены идентичные числа спайков и продолжение базы с использованием механизма spawn; запуск на реальной Windows и полном графе пока не проверен.

На полном плане `lesion_rates.csv` содержит средние частоты обоих MN9 при контроле и лезии по каждой частоте, а `lesion_classification.csv` отмечает отношение среднего левого MN9 ≤80% контроля хотя бы на одной частоте. Если контроль равен нулю, отношение не определяется; если нет положительного срабатывания и хотя бы одно отношение не определено, итог помечается `undefined`. В базе хранятся отдельные повторы и времена выполнения. `stimulated_grn` и `mn9` отмечены отдельно: у нейрона обнуляются исходящие связи, но его собственные спайки и внешняя стимуляция не выключаются.

Протокол 21 правого GRN, список 200 и частоты следуют авторскому ноутбуку Figure 1D/F. Публикация и ноутбук расходятся по стороне в другом описании Figure 1; нельзя считать результат полным воспроизведением статьи или биологической верификацией. Одинаковый seed у контроля и лезии не является проверкой идентичности входных спайковых времён. Разная реализация модели проверена против авторского кода на искусственной сети, но эквивалентность на полном графе не доказана. Сравнения с Princeton и кандидатными ID этот расчёт не делает.

Однако обновление файлов приложения может потребовать перезапуска: прежде остановите текущий процесс и запомните папку последнего прогона. Снимок не будет автоматически обновляться по мере продолжения исходного расчёта; для свежих данных повторите обзор. Не копируйте живую SQLite-базу обычным копированием как гарантированный резервный снимок.

### Новый общий набор без поиска старых SQLite

Если папки прежних лезий неудобно выбирать, в идее «Виртуальные лезии» откройте **«выборочные лезии» → «создать набор из топ-200»**. Один раз выберите полную папку топ-200, содержащую `summary.json`, `top200.csv`, `checkpoint.json` и все 30 файлов `counts_seed_*.npy`. Программа скопирует эти файлы в новый общий набор, перепроверит каждый массив и его рейтинг, исходные авторские данные и версии. При создании симуляции не выполняются. Старые базы лезий не ищутся, не используются и не изменяются. Неполное создание оставляет отдельную папку без манифеста; оно не перезаписывает существующие данные.

Общее хранилище находится в папке данных приложения, по умолчанию `fly-ideas\workspace\data\shiu-v630-shared`. Если в «папках и правах» папка данных переназначена, хранилище создаётся внутри неё. В диалоге показан фактический путь и есть кнопка «открыть папку набора». Названия папок внутри набора постоянны:

- `01_top200`: проверенная копия полного исходного отбора и 30 массивов;
- `02_controls_50Hz`: новая `lesions.sqlite3`, только 30 контрольных повторов на 50 Гц;
- `03_selected_lesions`: отдельная `selected_lesions.sqlite3` для 10 одиночных лезий, пяти пар и группы;
- `04_backups`: отдельные не перезаписываемые снимки SQLite после каждых десяти новых повторов и по завершении этапа;
- `05_reports`: отдельные копии планов, таблиц, графиков и снимков после каждого успешного этапа или обзора.

Папки прежних прогонов не переименовываются и не удаляются. В списке общих наборов показываются понятные названия и последний счётчик; если наборов несколько, выберите нужный по названию. Если хотите, чтобы разные идеи использовали одни данные, работайте с одним и тем же общим набором. При смене общей папки данных старый набор остаётся в прежнем месте; его следует сохранить и при необходимости снова выбрать прежнюю папку данных.

После создания нажмите **«план без симуляций»**. Затем **«рассчитать или продолжить 10 клеток»**: программа сначала выполнит недостающие 30 новых контролей, затем до 300 одиночных лезий. **«рассчитать или продолжить пары и группу»** завершит недостающие одиночные и добавит до 180 парных и групповых повторов. Для последующих запусков уже не нужно выбирать SQLite или папку топ-200: программа использует выбранный общий набор. Для таблиц во время или после прерывания используйте **«обзор сохранённых лезий»**. В идее «Индивидуальность из одинакового мозга» выберите **«контроли v630» → «построить обзор общих контролей»**; там используются новые общие контроли и создаются результаты только этой идеи.

Каждый повтор фиксируется транзакцией в управляемой базе. При повторном нажатии той же кнопки уже записанные повторы проверяются и пропускаются. Принудительно прерванный повтор может быть выполнен заново; после аварийной остановки проверяются целостность и контрольные суммы. Одновременная запись несколькими процессами в один общий набор блокируется. Перед тяжёлой симуляцией остановите остальные тяжёлые расчёты: 16 ГБ RAM не гарантируют достаточную память при одновременной работе моделей и Word. Оценки 300 одиночных и 180 парных/групповых повторов не включают время построения сети. Результаты анализа каждой идеи остаются в отдельной папке её прогонов с понятным названием этапа.

Резервные снимки в `04_backups` находятся на том же диске и не защищают от его поломки или удаления всей общей папки. Для надёжного хранения отдельно скопируйте **всю** папку набора на другой носитель после остановки расчёта. Google Drive или синхронизация не включаются автоматически; при использовании синхронизации файлы из папки данных включаются только при соответствующем выборе. Не заменяйте отдельный живой файл SQLite обычной копией во время записи.

Старый ручной режим с выбором баз сохранён внизу диалога для прежних экспериментов. Исходные авторские таблицы коннектома не копируются в общий набор: их нужно оставить доступными по выбранным в программе путям для новых симуляций. Полная научная эквивалентность и работа на реальной Windows не подтверждены одной только синтетической проверкой; это вычислительная модель, а не биологическая валидация.

### Пилот модельной индивидуальности v630

В идее «Индивидуальность из одинакового мозга» откройте **«контроли v630»**, выберите существующий общий набор и нажмите **«план пилота без симуляций»**. Для запуска отдельно нажмите **«рассчитать или продолжить пилот»**. План и «обзор сохранённого пилота» не запускают сеть. При недостаточной памяти симуляция не начинается: проверяется не менее 4 ГиБ доступной RAM перед каждым новым повтором; это не гарантия защиты от исчерпания памяти. Используется один процесс и по одному потоку основных численных библиотек. Закройте другие тяжёлые расчёты; проверка приложения не обнаруживает процессы, запущенные вне него.

План: 10 фиксированных вариантов × три входных seed 0–2 на 50 Гц, по 1 секунде модели, всего 30 новых повторов. Для варианта `v` генератор NumPy PCG64 с seed `1000+v` один раз генерирует независимые равномерные множители `[0,95; 1,05)` для всех исходных весов; их знак не меняется, веса варианта сохраняются на все три запуска и воспроизводятся при продолжении. Диапазон 5% не установлен биологическими данными. Используются готовые 30 контролей данного набора, не старая SQLite; сравнение со средним трёх контрольных seed выводится отдельно. Для воспроизводимости проверяются исходные данные, версии Python, NumPy, Brian2, контрольные повторы, код и отпечаток весов. Один и тот же seed не гарантирует совпадения входных времён между моделями.

Результаты пилота хранятся отдельно от исходной серии в `workspace/data/shiu-v630-individuality/<Study_ID>/pilot.sqlite3` или в соответствующей выбранной общей папке данных. База и исходный топ-200 набора не меняются, результат не добавляется к базе лезий. Каждый завершённый повтор фиксируется транзакцией; повторное нажатие кнопки продолжает недостающие повторы, при несовпадении протокола продолжение блокируется. Приложение пытается корректно остановить расчёт после текущего повтора по кнопке «остановить расчёт»; дождитесь сообщения о завершении. Резкое завершение или отключение может потребовать пересчёта последнего повтора. Не запускайте тот же пилот из двух экземпляров одновременно. Для резервного хранения скопируйте папку пилота на другой носитель после остановки; копия на том же диске не является независимой резервной копией.

Во вкладке результатов идеи находятся `report.txt`, `variants.csv`, `pilot_trials.csv`, `controls.csv`, согласованные снимки контролей и пилота, а также график `variants.png`. `network_and_simulation_seconds` включает создание сети и симуляцию, но не предварительную генерацию весов или проверку данных. Разброс средних вариантов и разброс повторов описательные, относятся к разным величинам и не доказывают индивидуальность, статистическую значимость или биологическую реалистичность. Это один коннектом, одна частота и три seed; устойчивость, входы, другие параметры и поведение необходимо исследовать отдельно. Автоматический тест использует искусственную малую сеть Brian2 и не подтверждает работу полного коннектома на Windows.

#### Продолжение пилота до 10 seed

После полного исходного пилота с 30 повторами выберите тот же набор в «Индивидуальность» → «контроли v630» и нажмите **«план продолжения до 10 seed»**. План проверяет согласованные снимки контрольной и исходной базы и не запускает сеть. **«Рассчитать или продолжить 70 повторов»** выполняет только дополнительные seed 3–9 для тех же 10 вариантов. Перед каждым вариантом повторно создаются его фиксированные веса, и их SHA-256 сверяется с исходным пилотом; при несовпадении выполнение останавливается. Входные файлы и версии Python, NumPy и Brian2 должны совпадать с прежним пилотом. Одинаковый seed не гарантирует одинаковые входные спайковые времена.

Новые повторы хранятся отдельно в `shiu-v630-individuality/<Study_ID>/extension_10seeds_v1/extension.sqlite3`; исходная база пилота и общая база лезий не изменяются. Каждый новый повтор сохраняется транзакцией. Кнопка остановки просит закончить текущий повтор, после чего можно продолжить той же кнопкой; аварийно прерванный повтор может потребовать пересчёта. **«Обзор продолжения на 10 seed»** не запускает симуляции и показывает имеющиеся данные, в том числе при прерывании. Для сохранности копируйте папку пилота целиком на другой носитель после остановки.

`report.txt`, `variants_10seed.csv`, `trials_10seed.csv` и `controls.csv` содержат вместе 30 прежних и до 70 новых повторов, а также отдельные контрольные данные. При неполном выполнении варианты имеют разное число seed и их средние нельзя прямо сравнивать. Выводы описательны: один коннектом, искусственное изменение весов, одна частота и 10 входов не доказывают устойчивые биологические индивидуальные фенотипы. Симуляция выполняется одним процессом, проверяет не менее 4 ГиБ доступной RAM и ограничивает потоки численных библиотек; это не исключает нехватку памяти. Перед симуляцией остановите другие тяжёлые задачи. На искусственной малой сети проверены новые повторы, идентичность весов, прерывание и продолжение; на полном графе в Windows это продолжение ещё не проверено.


### Проверка порядка вариантов на новых seed

В идее индивидуальности откройте **«контроли v630»**, выберите прежний общий набор и нажмите **«план проверки на новых seed»**. План не выполняет симуляции. Он проверяет 30 повторов исходного пилота и 70 повторов продолжения, фиксирует исходные средние и ранги в `frozen_plan.json`. После проверки плана нажмите **«рассчитать или продолжить проверку: 100 повторов»**. Это 10 прежних фиксированных вариантов весов × входные seed 10–19, 50 Гц, 1 секунда; все 100 повторов новые. Контроли seed 10–19 берутся из общего набора и не пересчитываются.

Новая база находится в `shiu-v630-individuality/<Study_ID>/holdout_10seeds_v1/holdout.sqlite3` внутри выбранной папки данных. План и исходные результаты фиксируются в метаданных базы **до первого нового повтора**; этот локальный файл не является внешней регистрацией. При несовпадении исходных данных, кода или весов продолжение останавливается. Исходные базы читаются через согласованные снимки и не меняются. Каждый новый повтор сохраняется транзакцией, кнопка остановки просит закончить текущий повтор; для продолжения нажмите ту же кнопку расчёта. Не запускайте одновременно два экземпляра приложения на этих данных. После остановки скопируйте папку пилота целиком на другой носитель.

**«Обзор проверки на новых seed»** не запускает симуляций. `report.txt`, `variants_holdout.csv`, `trials_holdout.csv`, `controls_holdout.csv`, `frozen_plan.json` и снимки SQLite находятся в папке результата. Основная метрика, Спирмен между средними левого MN9 по вариантам на seed 0–9 и 10–19, вычисляется только после 100/100 новых повторов; одинаковые средние получают средний ранг. Дополнительно выводятся Пирсон для левого MN9, Спирмен для правого и разница вариантов 10 и 9 на новых seed. Пара 9 и 10 выбрана после просмотра старых данных, порог успеха и статистический тест не заданы. При незавершённой проверке промежуточные средние основаны на разном числе seed и не годятся для сравнения порядка.

Это описательная проверка модельных вариантов, а не измерение индивидуальности животных. Одинаковый номер seed не гарантирует одинаковых входных спайковых времён в разных вариантах. Новые seed не доказывают статистическую значимость или биологическую реалистичность изменения весов. Один процесс, до одного полного повторения за раз; проверяются не менее 4 ГиБ доступной RAM, но этого может не хватить. Сохраните работу в Word, остановите другие тяжёлые задачи и следите за памятью. В тестах на малой сети проверены прерывание, возобновление и сохранность прежних данных; новый этап на полном графе в Windows ещё не проверен.

### Обновление приложения из ветки

Эту версию с кнопкой обновления сначала необходимо установить обычным способом: прежняя версия не умеет сама скачать ещё не существующую в ней кнопку. После этого в **«Мозг» → «Данные и окружение» → «Обновление приложения»** нажмите **«скачать обновление ветки»** и подтвердите загрузку. Источник фиксирован: публичный `Bergaff/fly`, ветка `arena/01a0b34a-fly`. Это снимок файлов коммита, не git merge; история или локальная ветка Git не переключаются. Перед загрузкой завершите расчёты и другие операции. Затем сохраните работу, закройте **все** экземпляры Fly Ideas и откройте `START.bat` двойным щелчком. Скачанные файлы применяются до запуска; если изменились зависимости, автоматически выполняется `npm ci` (нужен интернет). Не запускайте параллельно другую копию приложения из той же папки во время применения.

Приложение проверяет файлы архива по Git blob из дерева конкретного коммита GitHub, ограничивает пути и размеры, не заменяет `workspace`, пользовательские папки данных и рабочих проектов, конфиги и секреты. Файлы приложения, в том числе локально изменённые исходники, **могут быть заменены**: их прежние версии сохраняются в `workspace/.app-updates/backup-*`. Это не резервная копия на другом носителе. Файлы, удалённые из ветки, автоматически не удаляются. Файл `START.bat` автоматически не заменяется, так как он выполняется при обновлении; при изменениях именно этого файла понадобится отдельная ручная установка новой версии. Portable exe этим способом не обновляется. Для загрузки требуется доступ к GitHub и выбранный Python 3; приложение выполняет код из указанной ветки при следующем запуске.

При обнаружении повреждения или пересечения с пользовательскими папками обновление останавливается до замены. Если применение прервётся, при следующем запуске незавершённые изменения восстанавливаются из резервной копии, после чего нужно снова открыть `START.bat`. Если Python недоступен или npm не установил зависимости, запуск остановится с сообщением об ошибке; исправьте причину и снова откройте `START.bat`. Не удаляйте `.app-updates` во время восстановления. Механизм проверен автоматическими тестами и на архиве GitHub в Linux, но не на реальном Windows-компьютере.
